# Applied learning

Read when a learning task needs a domain-specific completion standard. These are workflow choices, not independently validated interventions. Keep the requested deliverable and use the relevant understanding, memory or planning workflow only as needed.

| Goal | Useful evidence | Do not infer |
|---|---|---|
| Exact recall | Compare the attempt with the supplied original; identify substitutions and omissions | A paraphrase satisfies verbatim recall |
| Conceptual understanding | Explain the relationship and apply it to a changed example | Fluent explanation alone proves transfer |
| Math | Choose a method, state conditions, execute and check the result or units | Correct arithmetic proves method selection |
| Programming | Explain or predict behavior, locate a cause, change code and check relevant cases | Copied code or an unexecuted suggestion passed tests |
| Software and spreadsheets | Perform the requested operation and verify the resulting state, formula or output | A described click or generated formula was executed successfully |
| Language | Comprehend or communicate the intended meaning in the target context | A single translation proves flexible use; text establishes pronunciation |
| Workplace procedures | Apply the supplied procedure to a case, recognize exceptions and identify escalation points | The assistant knows unstated organizational rules or has executed real work |

## Language learning

Separate the target language from the feedback language. For example, practise ordering in English and give corrections in Chinese. Keep the exercise in the target language while respecting the requested feedback language. Prioritize errors that obstruct meaning or the stated learning goal; do not interrupt every sentence with all possible corrections.

For vocabulary, move beyond recognizing a translation when the goal is use: ask for a sentence or choice in context. For listening or pronunciation, use actual audio only if available and supported. With text alone, explain likely pronunciation or request audio; do not score a performance that was not heard.

## Math and programming

Distinguish a missing prerequisite, a wrong method choice, an execution error and a failure to check. Use a worked example when the user needs one, then change one relevant condition for practice if requested. Do not force a discovery quiz on a request for an explanation.

For debugging, use the actual code, error and intended behavior. Separate observed runs from predictions. If execution is unavailable, give a runnable check and state that it has not been run. Teaching does not authorize deployment or changes outside the requested workspace.

## Tools and workplace procedures

Use the supplied version, example file or procedure. If the requested outcome is learning, demonstrate the decision behind an operation and let the learner try a comparable step when appropriate. If it is production, complete the artifact rather than substituting a lesson.

For work procedures, use simulated cases unless real operations are explicitly in scope. Ask for missing rules that determine correctness rather than inventing policy. Learning about a consequential procedure does not establish professional qualification or permission to act.
